# AleCoin — сайт (публичная часть + админка) — дизайн-спецификация

Дата: 2026-09-24
Статус: одобрено, готово к планированию реализации

## Контекст и цель

Продолжение проекта AleCoin после смарт-контракта (см.
`docs/superpowers/specs/2026-09-21-alecoin-design.md`,
`docs/superpowers/plans/2026-09-21-alecoin-smart-contract.md`). Контракт
`AleCoin.sol` уже написан, протестирован и задеплоен в тестовую сеть Polygon
Amoy (адрес `0x44e8b28c3b059EeAb4C84d78bffe1808067997b5`).

Эта спецификация покрывает вторую половину архитектуры из исходной спеки:
статичный сайт с публичной частью (баланс, перевод, история) и скрытой
админ-страницей (выдача наград). Как и контракт, сайт делится на отдельную
спецификацию и отдельный план реализации.

## Архитектура и стек

- **Next.js** (React), статическая сборка — тот же принцип хостинга, что и у
  проекта #1 («0x Coffee»): **GitHub Pages**, без собственного сервера.
- Работа с блокчейном — напрямую через **ethers.js v6** (та же библиотека,
  что уже использовалась в тестах контракта — единый подход, меньше новых
  понятий).
- Чтение и запись данных о блокчейне идут через кошелёк пользователя
  (MetaMask, `window.ethereum`), подключённый к сети через RPC.
- **RPC-провайдер:** личный ключ Alchemy, ограниченный в личном кабинете
  Alchemy по домену сайта (Allowed Origins) — чтобы скопированный ключ был
  бесполезен вне сайта. Публичный RPC Polygon (`rpc-amoy.polygon.technology`)
  не используется — на практике показал ненадёжную доступность (не удалось
  подключиться к нему в MetaMask даже через VPN во время деплоя контракта).
- Никакой базы данных и backend-сервера — весь код выполняется в браузере
  пользователя, вся проверка условий выдачи наград — в смарт-контракте.
- Адрес контракта и его ABI — одна конфигурационная константа в коде сайта.
  Сейчас указывает на Amoy; при переезде на Polygon mainnet меняется одно
  значение.
- **Локализация:** весь пользовательский текст интерфейса, включая
  сообщения об ошибках, — на простом русском языке, без жаргона.

## Страницы сайта

1. **`/` (главная)**
   - Подключение кошелька.
   - Баланс ALE подключённого кошелька.
   - Форма обычного перевода ALE на любой адрес (стандартный ERC-20
     `transfer`).
   - История операций — **только своя** (операции, где подключённый адрес
     является отправителем или получателем), не общая лента по всем
     держателям.
   - Если кошелёк не подключён — блок «как получить код» со ссылкой на
     Telegram владельца проекта, для тех, кто попал на сайт без ссылки-
     приглашения.

2. **`/claim`**
   - Разбирает `to`, `amount`, `nonce`, `sig` из query-параметров ссылки.
   - Показывает получателю «тебе полагается N ALE».
   - Просит подключить кошелёк получателя.
   - Кнопка «Получить» вызывает `claimReward(to, amount, nonce, sig)` от
     имени подключённого кошелька.
   - Если данные ссылки повреждены/неполные — понятное сообщение об ошибке
     вместо падения страницы.

3. **`/admin`** (скрытый маршрут)
   - Не в навигационном меню сайта, `noindex` в мета-тегах страницы и в
     `robots.txt` — маршрут не должен попадать в поисковые системы.
   - Подключение кошелька владельца.
   - Форма: адрес получателя + сумма ALE.
   - Генерация случайного `nonce` через `crypto.getRandomValues`.
   - Запрос подписи через MetaMask по формату EIP-712, полностью
     соответствующему тому, что проверяет контракт (домен
     `{ name: "AleCoin", version: "1", chainId, verifyingContract }`, тип
     `Claim(address to,uint256 amount,uint256 nonce)` — см. план контракта,
     Задача 3).
   - Сборка готовой ссылки `<сайт>/claim?to=...&amount=...&nonce=...&sig=...`
     и кнопка «скопировать».

## Подключение кошелька и работа с сетью

- Кнопка «Подключить кошелёк» доступна на всех трёх страницах, запрашивает
  доступ к `window.ethereum` через ethers.js (`BrowserProvider`).
- После подключения сайт проверяет текущую сеть кошелька. Если сеть не
  совпадает с нужной (Amoy сейчас, Polygon позже) — сайт сам инициирует
  стандартный запрос кошельку `wallet_addEthereumChain` с нужными
  параметрами сети (включая Alchemy RPC-URL), чтобы пользователю не нужно
  было вручную добавлять сеть, как пришлось делать при первичной настройке
  этого проекта.
- Баланс и история подгружаются после подключения к правильной сети, через
  запросы к контракту от лица подключённого кошелька.
- Перевод токенов (`/`) и получение награды (`/claim`) — обычные
  подтверждаемые в MetaMask транзакции.

## Обработка ошибок

Все сообщения — на русском языке, понятные не-технической аудитории:

- MetaMask не установлен в браузере → сообщение со ссылкой на установку.
- Сеть не подключена/не совпадает → сайт сам предлагает добавить/переключить
  (см. выше), отдельная ошибка показывается только если пользователь
  отклонил и этот запрос.
- Пользователь отменил подключение/подпись/транзакцию в MetaMask →
  сообщение «действие отменено», без падения страницы.
- Контракт отклонил операцию (revert из `require`) → технический текст
  переводится в понятное сообщение:
  - `"AleCoin: nonce already used"` → «эта награда уже была получена»
  - `"AleCoin: invalid signature"` → «ссылка повреждена или недействительна»
- Неполная или повреждённая ссылка на `/claim` (не хватает параметров,
  некорректный формат) → «ссылка повреждена», без падения страницы.
- Ошибка сети/RPC (Alchemy недоступен, обрыв соединения) → «не удалось
  подключиться к сети, попробуйте ещё раз позже».

## Тестирование

- **Автоматические тесты (Vitest)** — для логики, не требующей реального
  MetaMask: генерация nonce, сборка и разбор ссылки-приглашения, корректность
  структуры данных для EIP-712 подписи (сверка с форматом, который проверяет
  контракт).
- **Ручной прогон полного сценария** в тестовой сети Amoy перед переходом на
  Polygon mainnet: создание ссылки на `/admin` → отправка в Telegram →
  открытие `/claim` → получение токенов; включая проверку повторного
  использования той же ссылки (должно быть отклонено).

## Вне рамок этой спецификации

- Визуальный дизайн (цвета, шрифты, компоновка, айдентика) — прорабатывается
  отдельно на этапе реализации фронтенда (skill `frontend-design`).
- Пул ликвидности на Uniswap и доступность из России — отдельный
  опциональный пункт из исходной спеки, не связан с сайтом напрямую.
- Деплой в Polygon mainnet и связанная с ним настройка сайта (переключение
  конфигурационной константы адреса контракта) — выполняется после того, как
  контракт будет задеплоен в основную сеть.
